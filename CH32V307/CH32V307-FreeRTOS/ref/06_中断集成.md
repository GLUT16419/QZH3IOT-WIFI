# CH32V307 中断与 FreeRTOS 集成模块

包含：中断安全API规则、TIM2 Tick配置、中断优先级、中断ISR命名、临界区。

---

## 1. CH32V307 中断控制器 (PFIC)

CH32V307 使用 PFIC (Programmable Fast Interrupt Controller)，与标准 RISC-V 的 PLIC 不同。  
PFIC 在 `portmacro.h` 中提供了中断控制宏：

```c
portDISABLE_INTERRUPTS()    // 关闭全局中断
portENABLE_INTERRUPTS()     // 开启全局中断
```

## 2. 中断优先级配置

```c
// FreeRTOSConfig.h 中:
#define configPRIO_BITS                  2   // 2位优先级 (0-3)
#define configKERNEL_INTERRUPT_PRIORITY  0xFF  // 内核临界区用
#define configMAX_API_CALL_INTERRUPT_PRIORITY  0  // 可使用FreeRTOS API的最高优先级

// CH32V307 PFIC: 数值越小优先级越高
// 所以优先级 0 > 1 > 2 > 3
// 任何优先级 > 0 的中断都可以安全调用 FreeRTOS API
```

## 3. FreeRTOS Tick 中断配置

本项目使用 TIM2 作为 Tick 时钟源（而非 SysTick），配置如下：

```c
void TIM2_Init(void) {
    TIM_TimeBaseInitTypeDef TIM_TimeBaseStructure = {0};
    RCC_APB1PeriphClockCmd(RCC_APB1Periph_TIM2, ENABLE);

    // SystemCoreClock 通常为 144MHz, APB1 = 72MHz
    // TIM2挂载在APB1上，实际时钟=72MHz (如果APB1分频!=1则翻倍)
    // 产生500Hz中断: 72MHz / (72000 * 2) = 500Hz
    TIM_TimeBaseStructure.TIM_Prescaler = 72000 - 1;
    TIM_TimeBaseStructure.TIM_Period = 2 - 1;    // 2个计数 = 1个Tick
    TIM_TimeBaseStructure.TIM_CounterMode = TIM_CounterMode_Up;
    TIM_TimeBaseStructure.TIM_ClockDivision = 0;
    TIM_TimeBaseInit(TIM2, &TIM_TimeBaseStructure);
    TIM_ITConfig(TIM2, TIM_IT_Update, ENABLE);
    TIM_Cmd(TIM2, ENABLE);
    NVIC_EnableIRQ(TIM2_IRQn);

    // 与 WCHNET 协议栈共用 TIM2 时:
    // 注意与 WCHNET 的 TIM2 配置不同，需要根据具体应用调整
}
```

### Tick 中断处理函数

```c
void TIM2_IRQHandler(void) {
    if (TIM_GetITStatus(TIM2, TIM_IT_Update) != RESET) {
        TIM_ClearITPendingBit(TIM2, TIM_IT_Update);

        // 调度器已启动时调用
        if (xTaskGetSchedulerState() != taskSCHEDULER_NOT_STARTED) {
            xPortSysTickHandler();  // FreeRTOS Tick入口
        }
    }
}

// xPortSysTickHandler 定义在 FreeRTOS/portable/GCC/RISC-V/port.c
```

## 4. 中断安全API规则

**在中断服务函数中必须使用 FromISR 版本的 API，并检查是否需要上下文切换：**

```c
void USART1_IRQHandler(void) {
    BaseType_t xHigherPriorityTaskWoken = pdFALSE;

    if (USART_GetITStatus(USART1, USART_IT_RXNE) != RESET) {
        uint8_t data = USART_ReceiveData(USART1);

        // ✅ 正确: 使用 FromISR 版本
        xQueueSendFromISR(xQueue, &data, &xHigherPriorityTaskWoken);
        // 或
        xSemaphoreGiveFromISR(xSemBinary, &xHigherPriorityTaskWoken);
        // 或
        vTaskNotifyGiveFromISR(xTaskHandle, &xHigherPriorityTaskWoken);
        // 或
        xEventGroupSetBitsFromISR(xEventGroup, BIT_0, &xHigherPriorityTaskWoken);
    }

    // 如果 ISR 唤醒了更高优先级的任务，请求上下文切换
    if (xHigherPriorityTaskWoken) {
        portYIELD_FROM_ISR(xHigherPriorityTaskWoken);
    }
}
```

### API对照表

| 任务中调用 | 中断中调用 |
|------------|-----------|
| `xQueueSend()` | `xQueueSendFromISR()` |
| `xQueueReceive()` | `xQueueReceiveFromISR()` |
| `xSemaphoreGive()` | `xSemaphoreGiveFromISR()` |
| `xTaskNotifyGive()` | `xTaskNotifyGiveFromISR()` |
| `xTaskNotify()` | `xTaskNotifyFromISR()` |
| `xEventGroupSetBits()` | `xEventGroupSetBitsFromISR()` |
| `xTimerStart()` | `xTimerStartFromISR()` |

**注意**: `xSemaphoreTake()` 没有 FromISR 版本（中断中不能阻塞等待）。

## 5. 不可调用 FreeRTOS API 的中断

优先级高于 `configMAX_API_CALL_INTERRUPT_PRIORITY` (即优先级0) 的中断不能调用任何 FreeRTOS API。  
这些中断通常用于硬实时场景：

```c
// 优先级0 的中断 ISR 中:
// ❌ 不能调用 xQueueSendFromISR / xSemaphoreGiveFromISR 等
// ✅ 只能操作硬件寄存器
```

## 7. 临界区

```c
// 方法1: 任务级临界区 (关闭全局中断)
taskENTER_CRITICAL();
// 临界区代码 (不会被任何中断或任务切换打断)
taskEXIT_CRITICAL();

// 方法2: 调度器挂起 (不关中断，仅禁止任务切换)
vTaskSuspendAll();        // 挂起调度器
// 临界区代码 (中断仍可响应，但不会有任务切换)
xTaskResumeAll();         // 恢复调度器
```

---

*规则总结: 在 ISR 中始终使用 FromISR 后缀的 API，并传递 pxHigherPriorityTaskWoken 参数。*
